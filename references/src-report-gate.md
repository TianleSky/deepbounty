# SRC 报告门（DeepBounty）

> 继承自 tyang-skill2 `src-report-gate.md`，**执行方式强化**：本门不再只靠主代理自觉——
> `evidence_gate.py` 对 found 条目做机读硬校验（零脱敏/长度/请求响应段），
> `register_report.py` 登记前再过一遍。过不了门：矩阵记 `tested_not_found` / `doubtful`，
> **禁止**为凑数硬写低危报告（tyang-skill2 曾禁 C 类却批 131 个 low，本技能以脚本杜绝）。

目标：发现的洞尽可能是 SRC 都收的，并且每份都把危害打到该类能成立的最高一档。

---

## 1. found 之前必须同时成立

1. **兑现闭环**：最终效果成立（读到/改掉/登录成了/执行了具体对象）；他证在。
   自己的 200 / 回显 / 堆栈 = 自证，不算。
2. **业务危害**：一句话能写清平台损失了什么；预答辩四问能答
   （这数据该他看吗 / 攻击者图什么 / 和正常功能有何区别 / 影响面多大）。
3. **类型可报**：落在 §2 A，或 §2 B 且接链已兑现。落在 C 的**禁止 found（机读检查）**。
4. **L3 已做**：按 §3 打到终点，或负结果写明「危害边界」。L2 不先交、不先编号。
5. **同根因不重复**：已有同根因 VULN-VD 则本 URL 记 `duplicate_of`，不新开报告号。
6. **零脱敏全文（机读检查）**：请求与响应从当次实测原文贴入。全部请求头
   （含 Cookie、Authorization 及自定义认证头）、完整 body、完整响应头与响应体都在报告里。
   禁止打码、星号、省略号、只留关键字段。用代理 200 字节 preview 代替响应正文 = 证据不合格。
   → `evidence_gate.py` 检查：打码模式（`**`/`***`/`<redacted>`/「省略」）、报告长度 <2000、
   缺「请求」/「响应」段 = 硬错误。
7. **凭据可追溯（新增，机读检查）**：矩阵条目必须有 `cred_id`；越权类（AUTHZ002/004）
   必须能在 `cred/accounts.json` 找到 attacker+victim 双账号记录。

主代理验收：过不了门 → **拒绝**（标题加【已拒绝】），禁止「降到低危 approved」。
缺 L3 边界 → 退回补测。证据被打码或只贴片段 → 拒绝，退回补全文。

## 2. 能报 / 接链才报 / 永不当洞

挖掘时类型仍按 `vuln-checklist.md` 测。下面管的是能不能写成洞。

### A. 单独可报

- 水平越权读 / 写（读到他人非公开数据 / 改到他人状态）
- 垂直越权 / 未授权（真实业务数据或高权动作，不是登录页）
- 金额/数量篡改、券/积分/抽奖重复、支付逻辑、竞态双花
- 验证码/短信绕过（走完原业务：登录/注册/发码成功）
- 任意密码重置 / 账号接管（进入对方登录态）
- 存储型 XSS（第二账号触发执行）
- SQL 注入（取出真实数据，不是报错字样）
- SSRF（读到内网或元数据内容；**OOB 交互记录**为铁证）
- 命令执行 / 可解析的 webshell（无害命令有输出）
- 任意文件读（已知文件内容，且至少两个路径）
- XXE（OOB 带出文件内容或内网响应）

### B. 有接链才可报（单独出现只记线索，矩阵不要 found）

| 单独出现 | 接到什么才报 |
|---|---|
| 开放重定向 | OAuth/token 盗窃，或官方域登录流被接成钓鱼跳板 |
| CSRF | 真实跨站触发 **状态变更**（钱、权限、业务对象），站内第二视角确认 |
| CORS | `ACAC:true` **且** 读到账户/资金/PII |
| Host 头注入 | 重置邮件或缓存投毒已发出 |
| 点击劫持 | 敏感动作 PoC（改密、转账、授权），不是缺 XFO |
| 限流缺失 | OTP/重置码爆破 **成功进入业务** |
| JWT/签名 | 伪造 token **通过校验并完成业务请求** |
| 信息泄露 | 泄露物 **实际可用**（密钥调通、凭据登录、可关联真实用户） |

### C. 永远不当洞（测了记矩阵，不出 VULN-VD）

- 堆栈、类名、内部 IP、版本号、UUIDv1 MAC、Go binding 报错
- 缺 CSP/HSTS/XFO 等安全头
- Self-XSS、只读 CSRF、登出 CSRF
- 客户端风控参数可省略（`a_bogus` / `msToken` 一类）
- 分页无上限但没打出他人敏感数据
- 只伤害攻击者自己、自己改自己的参数
- 无安全边界穿越（输入原样拼回去、用记事本也能造出同样结果）

「敏感信息泄露」仍可测；没有「拿去用成功」就不得 found。

## 3. 深度：L2 最低，L3 默认

| 级 | 含义 | 出报告 |
|---|---|---|
| L0 | 线索（报错、差异、回显） | 不准 |
| L1 | 现象可复现 | 不准 |
| L2 | 动词兑现 + 他证闭环 + 过业务危害门 | 最低可报；**默认不交卷** |
| L3 | 接到该类 SRC 认的最高档业务危害 | **默认目标** |
| L4 | 量级抽样 | L3 后再做；无限制——量级证明不设条数上限 |

L3 是同一漏洞往上接到钱/PII/接管/内网，不是横向再扫无关接口。**无限制原则**：
危害验证不设操作类型/条数/账号归属限制（他人数据可读写、批量证明按需取样）。

| L2 已成立 | L3 默认终点 | 打不通时必须写清的边界 |
|---|---|---|
| 越权读到 1 条他人数据 | 能否枚举、是否含 PII/资金/身份、能否接到写/接管 | 不可枚举 / 无 PII / 写接口有校验 |
| 越权写成功 | 能否改钱、权限、绑定等关键状态 | 只能改无害字段 |
| 未授权 | 是否核心业务数据；能否批量 | 仅公开配置 |
| SSRF 出网 | 内网响应体、云元数据、接到已泄露内网主机 | DNS only / 仅外网 |
| SQL 注入 | 1 行业务数据 → 是否用户/订单表（最小样本） | 只能读 version |
| CSRF 改了状态 | 是否钱/券/权限；无交互或低交互 | 只读、SameSite 挡住 |
| CORS 带凭证 | 是否读到账户/提现/手机号 | 空数据、无 ACAC |
| 验证码绕过 | 登录成功 / 发短信成功 / 注册成功 | 只绕过了校验接口 |
| 存储 XSS | 第二账号执行；是否管理端/客服端 | 仅自己账号 |
| 支付/券/竞态 | 权益真实到账或可重复 | 前端可改、服务端复核 |
| XXE 回显 | 读出已知文件内容 / OOB 带出 | 仅报错无回显 |

打不通不是失败，是 L3 负结果，写进报告「危害边界」。

**无限制原则**：危害验证不设账号归属/操作类型/条数限制，以证明危害能力上限为准；
已造成的变更测试后尽量还原，不能还原的在报告中写清实际影响。
